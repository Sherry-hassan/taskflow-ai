* **2026-10-19 (MongoDB connection-failure handling fix)** — Committed `2272386` (2 files: `server/src/db/connection.js`, `server/src/index.js`), pushed to `master`. `connectDb()` previously called `mongoose.connect(uri)` with no explicit `serverSelectionTimeoutMS`, relying on the driver's own 30s+ default, and a connection failure's thrown error was never inspected for safety before deciding what to log. Now: (1) `connectDb()` accepts an explicit `serverSelectionTimeoutMS` (default `10_000`), so a misconfigured/unreachable MongoDB fails fast instead of hanging for 30+ seconds; (2) on failure, it parses the connection URI and throws a new `MongoConnectionError` whose message carries only an allow-listed diagnostic set (`host`, `port`, `dbName`, `replicaSet` option) — never the raw URI or the driver's own error message/stack, which can embed credentials — the same sanitized-logging discipline `utils/errorLogging.js` already applies elsewhere (M7, threat-model.md §7 item 3). `index.js`'s startup catch now logs `err.message` only when `err.name === 'MongoConnectionError'` (i.e., only the already-sanitized message built above); any other startup error still logs only `err.name`, unchanged from before.
